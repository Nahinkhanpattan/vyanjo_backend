Below is the COMPLETE, CONSOLIDATED DATABASE SCHEMA for your system, including meals, curry tokens, upgrades, delivery timing, grouping, addresses, common points, and GPS, with clear descriptions for every table and column.

This is now a final, production-grade schema for your meal + curry subscription web application.

📘 SYSTEM DATABASE SCHEMA (PostgreSQL)
1️⃣ users

Stores customers authenticated via Firebase phone auth

CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    phone_number VARCHAR(15) UNIQUE NOT NULL,
    name VARCHAR(100),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

One row per customer

phone_number is the primary identity

Future roles can be added without redesign

2️⃣ common_points

Shared delivery locations like hostels, PGs, offices

CREATE TABLE common_points (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(150) NOT NULL,
    address_line_1 TEXT,
    city VARCHAR(100),
    state VARCHAR(100),
    pincode VARCHAR(10),
    latitude DECIMAL(9,6),
    longitude DECIMAL(9,6),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Used when multiple users share one delivery point

Latitude/longitude optional

Referenced from addresses

3️⃣ addresses

Stores user delivery addresses

CREATE TABLE addresses (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,

    tag VARCHAR(50) NOT NULL, -- home, work, office, other
    address_line_1 TEXT NOT NULL,
    address_line_2 TEXT,
    landmark TEXT,

    city VARCHAR(100) NOT NULL,
    state VARCHAR(100) NOT NULL,
    pincode VARCHAR(10) NOT NULL,

    latitude DECIMAL(9,6),
    longitude DECIMAL(9,6),

    common_point_id UUID REFERENCES common_points(id),

    phone_number VARCHAR(15),
    is_primary BOOLEAN DEFAULT FALSE,

    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Multiple addresses per user

One primary address enforced in backend

Can optionally point to a common_point

GPS coordinates are optional

4️⃣ meal_packages

Defines base meal subscription plans

CREATE TABLE meal_packages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(150) NOT NULL,

    diet_type VARCHAR(20) NOT NULL CHECK (diet_type IN ('veg', 'non_veg')),
    cuisine_type VARCHAR(20) NOT NULL CHECK (cuisine_type IN ('south_indian', 'north_indian')),

    includes_breakfast BOOLEAN DEFAULT FALSE,
    includes_lunch BOOLEAN DEFAULT FALSE,
    includes_dinner BOOLEAN DEFAULT FALSE,
    includes_snacks BOOLEAN DEFAULT FALSE,

    duration_days INTEGER NOT NULL, -- 7 or 30

    default_container VARCHAR(20) NOT NULL CHECK (default_container IN ('plastic', 'steel')),
    allows_container_choice BOOLEAN DEFAULT FALSE,

    allows_diet_upgrade BOOLEAN DEFAULT FALSE,
    allows_cuisine_upgrade BOOLEAN DEFAULT FALSE,

    price NUMERIC(10,2) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,

    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Each row = one purchasable meal plan

No dynamic pricing

Upgrades handled separately

5️⃣ subscriptions

User’s active or historical meal subscriptions

CREATE TABLE subscriptions (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    meal_package_id UUID NOT NULL REFERENCES meal_packages(id),
    address_id UUID NOT NULL REFERENCES addresses(id),

    container_type VARCHAR(20) NOT NULL CHECK (container_type IN ('plastic', 'steel')),

    start_date DATE NOT NULL,
    end_date DATE NOT NULL,

    status VARCHAR(20) NOT NULL CHECK (status IN ('active', 'completed', 'cancelled')),

    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

One active subscription per user (logic-level rule)

Address fixed for subscription duration

6️⃣ weekly_menus

Weekly menu per diet & cuisine

CREATE TABLE weekly_menus (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    diet_type VARCHAR(20) NOT NULL CHECK (diet_type IN ('veg', 'non_veg')),
    cuisine_type VARCHAR(20) NOT NULL CHECK (cuisine_type IN ('south_indian', 'north_indian')),
    week_start_date DATE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE (diet_type, cuisine_type, week_start_date)
);

Description

Shared by all users in that category

Immutable once published

7️⃣ weekly_menu_items

Actual food items per menu

CREATE TABLE weekly_menu_items (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    weekly_menu_id UUID NOT NULL REFERENCES weekly_menus(id) ON DELETE CASCADE,

    item_type VARCHAR(20) NOT NULL CHECK (
        item_type IN (
            'breakfast', 'lunch', 'dinner', 'snacks',
            'curry_lunch', 'curry_dinner'
        )
    ),

    item_name TEXT NOT NULL
);

Description

Supports both meal and curry menus

Multiple dishes per meal allowed

8️⃣ delivery_time_slots

Defines reusable delivery windows

CREATE TABLE delivery_time_slots (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(50) NOT NULL,
    start_time TIME NOT NULL,
    end_time TIME NOT NULL,
    is_active BOOLEAN DEFAULT TRUE
);

Description

Used by meals and curry orders

Admin-managed

Example: 7–8 AM, 12–1 PM

9️⃣ delivery_groups

Groups multiple items into one delivery

CREATE TABLE delivery_groups (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    service_date DATE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Used when:

Tiffin + lunch together

Tiffin + curry together

🔟 subscription_meals

Generated meal schedule per subscription

CREATE TABLE subscription_meals (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    subscription_id UUID NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,

    service_date DATE NOT NULL,

    item_type VARCHAR(20) NOT NULL CHECK (
        item_type IN ('breakfast', 'lunch', 'dinner', 'snacks')
    ),

    delivery_slot_id UUID REFERENCES delivery_time_slots(id),
    delivery_group_id UUID REFERENCES delivery_groups(id),

    is_paused BOOLEAN DEFAULT FALSE,

    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),

    UNIQUE (subscription_id, service_date, item_type)
);

Description

One row = one meal occurrence

Supports pausing, timing, grouping

1️⃣1️⃣ meal_pauses

Audit log for paused meals

CREATE TABLE meal_pauses (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    subscription_id UUID NOT NULL REFERENCES subscriptions(id) ON DELETE CASCADE,
    meal_date DATE NOT NULL,
    meal_type VARCHAR(20) NOT NULL CHECK (
        meal_type IN ('breakfast', 'lunch', 'dinner', 'snacks', 'all')
    ),
    paused_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Backend enforces pause before 8 PM IST

Updates subscription_meals.is_paused

1️⃣2️⃣ curry_token_packages

Purchasable curry token bundles

CREATE TABLE curry_token_packages (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL,
    diet_type VARCHAR(20) NOT NULL CHECK (diet_type IN ('veg', 'non_veg')),
    token_count INTEGER NOT NULL,
    validity_days INTEGER NOT NULL,
    price NUMERIC(10,2) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Token-based curry access

Veg & non-veg separated

1️⃣3️⃣ user_curry_wallets

Tracks remaining curry tokens

CREATE TABLE user_curry_wallets (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    diet_type VARCHAR(20) NOT NULL CHECK (diet_type IN ('veg', 'non_veg')),
    total_tokens INTEGER NOT NULL,
    used_tokens INTEGER DEFAULT 0,
    valid_until DATE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    UNIQUE (user_id, diet_type)
);

Description

One wallet per user per diet

Remaining tokens = total − used

1️⃣4️⃣ curry_orders

Consumes curry tokens

CREATE TABLE curry_orders (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id),
    wallet_id UUID NOT NULL REFERENCES user_curry_wallets(id),

    cuisine_type VARCHAR(20) NOT NULL CHECK (cuisine_type IN ('south_indian', 'north_indian')),
    order_date DATE NOT NULL,

    delivery_slot_id UUID REFERENCES delivery_time_slots(id),
    delivery_group_id UUID REFERENCES delivery_groups(id),

    status VARCHAR(20) NOT NULL CHECK (status IN ('ordered', 'cancelled', 'fulfilled')),
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Each order consumes one token

Can be grouped with meals

Can be future-dated

1️⃣5️⃣ upgrade_prices

Defines upgrade cost rules

CREATE TABLE upgrade_prices (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    upgrade_type VARCHAR(30) NOT NULL CHECK (
        upgrade_type IN ('veg_to_nonveg', 'south_to_north')
    ),
    scope VARCHAR(20) NOT NULL CHECK (scope IN ('meal', 'day', 'week')),
    meal_type VARCHAR(20) CHECK (meal_type IN ('breakfast', 'lunch', 'dinner')),
    price NUMERIC(10,2) NOT NULL,
    is_active BOOLEAN DEFAULT TRUE
);

Description

Central pricing control for upgrades

1️⃣6️⃣ subscription_upgrades

Applied temporary upgrades

CREATE TABLE subscription_upgrades (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    subscription_id UUID NOT NULL REFERENCES subscriptions(id),

    upgrade_type VARCHAR(30) NOT NULL CHECK (
        upgrade_type IN ('veg_to_nonveg', 'south_to_north')
    ),

    scope VARCHAR(20) NOT NULL CHECK (scope IN ('meal', 'day', 'week')),
    meal_type VARCHAR(20) CHECK (meal_type IN ('breakfast', 'lunch', 'dinner')),

    start_date DATE NOT NULL,
    end_date DATE NOT NULL,

    price NUMERIC(10,2) NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

Description

Temporary overrides

Does not mutate base subscription

1️⃣7️⃣ notifications

In-app user notifications

CREATE TABLE notifications (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    title VARCHAR(150) NOT NULL,
    message TEXT NOT NULL,
    is_read BOOLEAN DEFAULT FALSE,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

 Below is a clear, backend-centric system model explanation of how your backend behaves, what APIs (routes) are needed, and how data flows, with real examples.

🧠 SYSTEM MODEL – BACKEND BEHAVIOR & API DESIGN

Your backend is a single service that manages:

Authentication handshake (Firebase)

Subscription logic

Curry token wallet

Meal scheduling

Pausing & upgrades

Delivery timing & grouping

Menus & notifications

No delivery routing, no agents, no restaurants.

1️⃣ Backend Architecture (High Level)
Stack (recommended)

Backend: Python (FastAPI / Django REST)

DB: PostgreSQL

Auth: Firebase Phone Auth (ID token verification)

Timezone: IST (Asia/Kolkata)

Request Lifecycle
Client (Web)
  → Firebase OTP Login
  → Receives ID Token
  → Calls Backend API with ID Token
  → Backend verifies token
  → Maps phone number → user

2️⃣ Authentication Flow (Every Request)
Middleware Behavior

Extract Firebase ID token from headers

Verify token with Firebase Admin SDK

Extract phone number

Find or create users record

Attach user_id to request context

No password logic in backend.
3️⃣ MODULE-WISE BACKEND BEHAVIOR & ROUTES

➤ POST /auth/login

Purpose

Sync Firebase user with backend DB

Flow

User profile returned

Response

  "phone": "+91xxxx",
  "name": null
}
